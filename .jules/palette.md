## 2024-05-18 - Missing Interactive States on Custom "Selectable Cards"
**Learning:** In `@workspace/maakon-web`, developers often build custom radio-button-like selection components (like `AccountTypeStep.tsx` buttons) using standard HTML `<button>` elements, but only rely on custom border/background classes for the "selected" state. This breaks semantic meaning for assistive technologies, which won't announce when an item is selected, and also causes keyboard users to lose track of where they are if custom focus states aren't also mapped.
**Action:** When creating or reviewing custom radio/selection buttons, ensure `aria-pressed` (or `aria-selected` if part of a group/tablist) is dynamically toggled based on the selected state, and `focus-visible:ring-2` (and related ring styling) is explicitly added to ensure robust keyboard navigation support.
